Identify the input path Windows sees

  1. Use Windows 10 version 1709 or later or Windows 11 x64. Remove overlapping combined Interceptor installations before switching editions. Follow the installation and restart instructions for the controller edition.
  2. Connect your gamepad using the exact connection you want to test. Extract the examples ZIP and open InterceptorExampleUI.exe as administrator.
  3. Select the family tab and move one control at a time. Check that the viewer changes for your controller and note whether the source appears as HID, XInput/XUSB, XInputHID or GIP. Use Diagnose when the device is present but no reports appear.
  4. Use Stop and close the viewer before running a remapping example. Use one capture application at a time.

Controller names such as Xbox, DualShock 4 or DualSense describe product families. Your cable, receiver, firmware and Windows driver determine the input path. A supported USB configuration and a Bluetooth configuration can behave differently. Read the versioned compatibility guide.

Try a stick deadzone

In a local controller testing application, observe the unmodified movement first. Then run ExamplesConsole\Controller_04_Deadzone_50.exe from the examples ZIP. Move the same stick slowly and compare the output with your baseline. Close the example and confirm normal input returns. The one-hour demo allowance is shared across apps for the current Windows kernel boot.

What was validated

The published 1.0.13.0 release documents Microsoft signature checks and separate user-mode fixtures. The physical-controller comparison above is a test to perform on your own controller and connection. Read the published validation scope.

The benchmark lab also publishes separate virtual Xbox 360 (XInput) and DualShock 4 (HID) runs with independently observed modified reports. Each run records its driver version, profile and receiver. Inspect the controller results and raw data.
