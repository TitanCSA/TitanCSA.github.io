Interception V2 is TitanCSA’s Windows compatibility driver for applications built with the C SDK from Francisco Lopes’s original Interception project. V2 packages that SDK and the original examples with its own driver.

Check requirements and install the demo

The package targets Windows 10 version 1709 or later and Windows 11 x64. It supports compatible keyboard and mouse HID paths. For an existing application built with the original C SDK, start with its current interception.dll. For a new build, use the matching x86 or x64 import library and DLL from the demo archive.

  1. In a test environment, close your existing capture application. Follow the removal instructions of the old Interception driver or overlapping Interceptor edition first, then restart Windows.
  2. Extract the demo ZIP. From an administrator Command Prompt opened in the extracted Interception folder, run the bundled setup.
  3. Restart if requested. With a single capture application open, test your intended keyboard or mouse and confirm the normal input reaches a local editor. For a mapped key, check press and release, then exit and confirm ordinary input is restored.
"command line installer\install-interception.exe" /install

Use /uninstall with the same installer to remove the demo. If requested, restart Windows to finish removal. In the demo, the first successful context starts the one-hour allowance for that Windows boot.

Check hardware IDs before remapping

The downloadable C example opens a context, lists available keyboard and mouse hardware IDs and destroys the context. It sets no input filter. Device numbers can change after reboot or reconnect, so re-identify the device before applying a mapping.

Save the C file in the extracted Interception directory and open the Visual Studio developer command prompt for your application's architecture. This is the x64 build. For x86, use the x86 developer prompt and replace both library\x64 paths with library\x86.

cl /nologo /W4 /MT /I library interception-device-inventory.c /link /LIBPATH:library\x64 interception.lib
copy /y library\x64\interception.dll .

The /MT option builds the example with a static C runtime so it can start on a clean VM with the matching interception.dll.

Run the sample as administrator after installing the demo. A supported fixture should produce a line with its device class, number and hardware ID. The sample compiled against both import libraries in the signed-demo ZIP. Compatibility with a specific application still needs a live test with that application's devices and filters.

In Windows 11 build 26100 with Secure Boot, the signed 2.0.0.0 demo installed and restarted successfully. Both x86 and x64 builds of this sample listed one mouse after setup. After uninstall and restart, the driver service was gone and both samples returned their expected context-open error. See the exact archive, DLLs and test results
