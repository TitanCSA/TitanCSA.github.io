Installateur, pilote et SDK

Pour essayer une démo, commence par l’installateur. Pour écrire ton propre programme, prends le SDK.

Read in English

Installateur
Lance ce programme pour installer le pilote et essayer la démo.
Pilote
Windows charge ses fichiers .sys pour que l’application puisse utiliser un périphérique réel ou virtuel pris en charge.
SDK
Le code et les exemples pour appeler le pilote depuis ta propre application.

Essayer un pilote

  1. Choisis ton édition. Télécharge son installateur dans le tableau.
  2. Lance l’installation en administrateur. Pour un ZIP, décompresse-le d’abord. Clique sur Install dans l’installateur graphique ou suis la commande Interception V2.
  3. Redémarre si l’installateur le demande. Ouvre l’exemple indiqué sur la fiche et suis son premier test.

Tu changes d’édition Interceptor pour les mêmes périphériques ? Désinstalle l’ancienne édition et redémarre avant d’installer la nouvelle.

Compiler le premier test SDK

Installe Visual Studio 2022 avec le développement de bureau en C++, CMake 3.20+ et Python 3.10+. Décompresse le ZIP de premiers tests SDK, ouvre PowerShell dans ce dossier et lance une commande.

python scripts/test_first_sdk.py vdevice --run

Le script vérifie le SHA-256 du ZIP exact, compile l’exemple et l’exécute. Remplace vdevice par l’identifiant de l’édition dans le fichier d’intégration. Pour la bibliothèque Interception V2 en 32 bits, ajoute --arch x86.

  • Pour Interceptor et Vdevice, Driver answered signifie que le pilote a répondu. Windows 2 indique que le test ne trouve pas son interface.
  • Pour Interception V2, le test fonctionne sans pilote et affiche 10 emplacements clavier et 10 souris. Pour voir les périphériques connectés, utilise ensuite l’exemple d’inventaire. Celui-ci ouvre un contexte et démarre la démo.
  • Pour Titan Audio Link, 0 endpoint Titan est normal avant l’installation. Le test compte les entrées et sorties audio Titan. Il ne joue et n’enregistre aucun son.

Les premiers tests ne capturent aucune entrée et ne créent aucun périphérique virtuel. Ils ne démarrent pas le compteur de démo. Le numéro de version du pilote et le numéro de l’interface affiché par le test sont deux informations différentes.

Dans ton application C++, utilise les fichiers .h et .cpp du même ZIP. Pour Interception V2, lie le fichier .lib et place la DLL de la bonne architecture à côté de ton programme. Le fichier d’intégration donne les noms des fichiers et les définitions de compilation, dont les réglages Unicode requis par les SDK C++.

Le fichier d’intégration contient le SHA-256 de chaque installateur, exemple et SDK. Le guide de vérification d’un pilote Windows montre comment comparer un téléchargement à l’empreinte publiée.

Pour les tests automatisés en VM, demo.console_setup donne le fichier exact, les arguments d’installation et de désinstallation, le code de redémarrage et le résultat vérifié.
