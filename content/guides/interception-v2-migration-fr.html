Continuer à utiliser une application Interception sous Windows

Interception V2 fournit un pilote clavier et souris pour les applications qui utilisent le SDK C d’Interception. Essaie d’abord ton application existante avec la démo.

Télécharger la démo {{INTERCEPTION_V2_DEMO_VERSION}}Empreintes SHA-256

Installer et tester

  1. Vérifie que ton PC utilise Windows 10 version 1709 ou plus récente, ou Windows 11, en 64 bits. Ferme ton application. Si l’ancien pilote Interception ou une édition Interceptor clavier et souris est installé, désinstalle-le puis redémarre.
  2. Décompresse le ZIP. Ouvre une invite de commandes en tant qu’administrateur, place-toi dans le dossier Interception extrait et lance cette commande. 
    "command line installer\install-interception.exe" /install
  3. Redémarre si l’installateur le demande. Garde le fichier interception.dll fourni avec ton application, lance-la en tant qu’administrateur et vérifie le clavier ou la souris dans cette application.

Après chaque démarrage de Windows, la démo dure une heure à partir du moment où une application se connecte au pilote pour la première fois. Pour retirer le pilote, remplace /install par /uninstall et redémarre si demandé.

Intégrer le SDK et lister les périphériques

Le ZIP comprend l’en-tête C, la bibliothèque .lib pour la compilation et la DLL à placer près de ton programme. Choisis les fichiers x86 ou x64 selon l’architecture de ton application. Le pilote s’installe uniquement sous Windows x64.

Télécharge l’exemple C d’inventaire et enregistre-le dans le dossier Interception extrait. Ouvre l’invite de commandes développeur Visual Studio x64 dans ce dossier et lance les lignes suivantes. Pour compiler en x86, ouvre l’invite x86 et remplace les deux chemins library\x64 par library\x86.

cl /nologo /W4 /MT /I library interception-device-inventory.c /link /LIBPATH:library\x64 interception.lib
copy /y library\x64\interception.dll .

Une fois le pilote installé, lance interception-device-inventory.exe en tant qu’administrateur. L’exemple liste les identifiants matériels accessibles sans activer de filtre. L’ouverture réussie du contexte démarre la démo. Réidentifie ton périphérique après un redémarrage ou une reconnexion.

Après installation de la démo 2.0.0.0 dans une VM Windows 11, les deux versions de l’exemple ont chacune détecté une souris. Rapport d’installation et de désinstallation.

Lors d’un essai distinct de la démo 2.0.0.0 sous Windows 11, l’inventaire x64 a ouvert un contexte à 59 min 10 s. À 60 min 50 s, le pilote chargé a refusé un nouveau contexte. Le redémarrage a rétabli l’accès. Voir les mesures et la désinstallation.

Tu peux aussi décompresser le ZIP d’exemple Rust et lancer cargo run --locked pour vérifier le premier emplacement clavier.

Essayer le SDK Python

Sous Windows, utilise Python 3.10 ou plus récent en 64 bits. Place le paquet Python et le script de test dans le même dossier. Ouvre PowerShell dans ce dossier.

python -m pip install .\{{INTERCEPTION_V2_PYTHON_WHEEL_FILE}}
python .\python-interception-v2-check.py

Le test classe l’emplacement 1 comme clavier et le 11 comme souris. Ce sont des emplacements réservés par la bibliothèque. Cette étape fonctionne avant l’installation du pilote.

Après installation de la démo {{INTERCEPTION_V2_PYTHON_TESTED_DEMO}}, ajoute --inventory pour compter les périphériques détectés. Lance cette commande en administrateur. L’ouverture du contexte démarre le compteur de démo.
