First API checks and the Node.js 1.0.1 archives

Read driver status from your project

After running the npm command above, save node-sdk-status.cjs in your project folder. Open PowerShell in that folder and run the command below for the combined Interceptor edition.

node node-sdk-status.cjs interceptor

The script prints driver status. Windows 2 means this call could not find the driver interface. Use the edition ID and command in the integration manifest for the other bindings.

For a Gallery module, use the PowerShell status sample after installing the matching module. The Interception V2 check classifies a library slot and works before driver installation.

Use the reviewed Node.js 1.0.1 packages

The publisher's GitHub release supplies Windows x64 Node.js 1.0.1 archives and a SHA-256 list. Download your edition and run npm install ./PACKAGE-1.0.1.tgz with the downloaded file name. The npm commands in the table install the registry's 1.0.0 versions.

  • interceptor-sdk 1.0.1
  • interceptor-keyboard-mouse-sdk 1.0.1
  • interceptor-gamepad-controller 1.0.1

The three 1.0.1 archives report the matching InterceptorSetup.exe when Windows error 2 indicates a missing driver. Each archive was installed from its GitHub URL. Node.js 24.21.0 also read driver status for each matching signed demo on Windows 11 build 26100 with Secure Boot. The checks used the read-only info() example.

Verify the Python installation first

The Python wheel requires Python 3.10 or later on Windows x64. It includes the native bridge for the combined Interceptor 1.4.22.0 driver. For a live test, use that driver and the documented info() read-only query. The following import check works before installing a driver.

from importlib.metadata import version
from interceptor import Interceptor

print(version('interceptor-multilang'))

The exact Windows wheel installed into a temporary Python directory and reported 1.0.2. Its wheel and source archive both matched the SHA-256 published on PyPI. Read the Python API and driver requirements.

After setup, with Interceptor() as io: print(io.info()) reads driver status. In a test without the combined driver, the wheel loaded its native bridge and returned Windows error 2 with the corrected setup instructions. Use the matching combined demo’s InterceptorSetup.exe, then restart if requested. Install.cmd is available in the full MultiLang ZIP.

The NuGet wrapper requires .NET 8 or later on Windows x64. It includes the same native bridge as the Python wheel. After setup, Interceptor.GetInfo() queries the matching driver without starting input capture. The exact public 1.0.2 package returned the corrected one-line setup message on a machine without that driver.

Check the PowerShell modules

All five Gallery modules at 1.0.0 imported on Windows x64 with PowerShell 7.6.6. The Interceptor-family status calls and Vdevice's status operation reported Windows error 2 with the matching driver absent. If the Interceptor module mentions Install.cmd, use InterceptorSetup.exe from your edition's signed demo or the installer supplied in its commercial ZIP. For Vdevice, use the matching VdeviceSetup.exe. Restart Windows if setup requests it. Choose the correct driver edition.

The InterceptionV2 module's check operation identifies keyboard and mouse numbers in the original C API. Use the device inventory example to verify a live driver and available devices.

Start with a known result

  • Try the Vdevice mouse example to confirm the Windows device path.
  • Compile the Interception V2 device inventory with the x86 or x64 libraries from the signed demo.
  • Compare the driver demos and commercial packages before switching editions.
