Switch between Interceptor and the original driver

For compatible HID keyboards and mice, Setup records the original driver package before installing Interceptor. Restore that package when you need to access settings in the manufacturer’s software, then switch back to Interceptor to capture input.

  • Get_Input_Driver_Bindings() lists the current driver and Windows instance ID for each HID keyboard or mouse.
  • Set_Input_Driver_Mode(instance, true) restores the recorded original driver. Pass false to switch back to Interceptor.

Both functions are in the C++ SDK for Demo and Release. Close capture and run the switch as administrator. If the switch returns 3010, restart Windows before continuing. C++ API reference

Use the read-only C++ example to list the current driver for each compatible input device before switching. Compile it with the two-file SDK. Instance IDs can contain serial numbers, so review the output before sharing it.

In a Windows 11 VM with Secure Boot, demo v1.0.5.4-demo-r3 switched one virtual USB mouse to its Windows driver and back to Interceptor. A second virtual mouse stayed on Interceptor. See the recorded driver bindings.

When to use it

Use a second keyboard for accessibility shortcuts or a macro pad while keeping your main keyboard’s normal behavior. Device attribution lets the same key have a different role on each keyboard.

First validation

Use the signed demo on Windows 10 1709+ or Windows 11 x64. In the input viewer, press a key on each keyboard and confirm the source before changing any mapping. Test an ordinary key with a single capture application and use Stop to release capture. The demo allows one hour per Windows kernel boot.
